# The Architecture Matrix

## What each governance architecture gains — and what it risks

**[The Governance Spectrum](/arkitektur/spektrum/)** shows **where** we can move. The matrix shows **what happens along the way**: which properties get stronger, and which get temporarily or permanently weaker.

Below, the twelve architectures are scored (1–10, higher is better for that property) across ten dimensions. These are **design hypotheses, not empirical measurements** — useful mainly for making the shape of the trade-offs visible, not as an authoritative answer.

## The valley is real

Look especially at the sequence 1 → 5, and at 4 → 7 → 8 → 9. **Coordination** and **accountability** dip before the new, distributed forms of the same capability have had time to mature.

A centralized system has a simple accountability chain: *who did it? → the Government.* A polycentric system risks instead becoming: *"It was the municipality." "No, the region." "No, the agency." "No, the citizens' council."* That can be devastating unless the accountability architecture develops **before** authority is spread out.

The same pattern applies to speed: more participants and more coordination can initially make decisions *slower*, even though a mature distributed system can eventually become more responsive because decisions are made closer to the source of information.

---

## The principle: capability before decentralization

The naive reform order is:

> decentralize → decentralize further → build autonomous institutions → eventually build coordination.

That is dangerous. The more robust order is the reverse:

> build coordination intelligence → build epistemic diversity → build accountability across nodes → distribute authority → connect the distributed nodes → make the architecture adaptive.

In other words: **don't remove the old coordination machinery until the new one is in place.**

This pattern — a destination can be superior while the path toward it temporarily makes the system worse — is the core of what we call the **transition valley**. We map it in detail, with a full breakdown of five distinct "valleys" (coordination, accountability, speed, knowledge and legitimacy) and concrete bridge institutions for each, in the upcoming **Transition** section.

Two principles already make it possible to start crossing the valley safely:

**[Adaptive Subsidiarity →](/arkitektur/adaptiv-subsidiaritet/)** — decisions only move downward when it actually improves system performance, and can move back up if it doesn't.

**[Meta-Governance →](/arkitektur/meta-styrning/)** — a permanent capacity to monitor whether the allocation of authority is still correctly designed, rather than assuming it always will be.
